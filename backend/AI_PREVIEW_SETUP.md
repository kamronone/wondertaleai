# WonderTale AI: подключение настоящей AI-генерации в Preview

Состояние: серверный код готов к проверке с настоящим OpenAI API, но **включение провайдера и успешный реальный вызов не подтверждены**. ChatGPT-подписка и ChatGPT-сессия не являются серверным API-ключом.

## Где настраивать

Изолированный проект Vercel: **wondertaleai-api-preview**. Не использовать Frontend, Production или публичные клиентские переменные для секретов.

В Settings → Environment Variables для **Preview** разместить:

| Имя | Значение и назначение |
| --- | --- |
| `OPENAI_API_KEY` | Секретный проектный ключ OpenAI Platform. Вводить только в интерфейсе Vercel, не в GitHub, коде, скриншотах или чате. |
| `ENABLE_TEXT_AI` | `true` только после проверки ключа, биллинга, согласия на передачу данных и разрешённого пилотного аккаунта; в остальных случаях `false`. |
| `AI_ALLOWED_EMAILS` | Email адрес(а) пилотных родительских аккаунтов; не включать весь интернет. |
| `STORY_TEXT_MODEL` | Модель Responses API, доступная именно для API-проекта. Если не задана, используется значение по умолчанию из `ai_generation.py`. |
| `MAX_AI_STORIES_PER_DAY` | Консервативный общий суточный предел (код по умолчанию использует 10). |

`AUTH_SECRET`, `DATABASE_URL`, `CORS_ORIGINS`, `PUBLIC_APP_ORIGIN` и email verification должны настраиваться как отдельные серверные средства защиты. Не переключать Production.

## Проверка до реальных запросов

1. Подтвердить владельца AI-проекта, права на использование API, расходы и маршрут обработки данных детей.
2. Убедиться, что `/api/ready` отвечает без секретов и база доступна.
3. Войти под тестовым родительским аккаунтом, проверить `GET /api/billing/status`: `ai_pilot_access: true`, `ai_remaining_today > 0`.
4. В конструкторе выбрать **AI (аккаунт)**. Использовать вымышленное имя ребёнка; фотографии не загружать.
5. Отправить тестовую сказку и проверить, что `POST /api/books/generate` вернул статус 201, 8 страниц, правильный язык, что книга принадлежит только этому аккаунту и читается.
6. Проверить 403, 429, 502, 503 и истечение сессии. Убедиться, что неуспешные вызовы не списывают лимит и не создают чужих книг.
7. После теста при необходимости вновь поставить `ENABLE_TEXT_AI=false`.

## Что делает код

- Запросы выполняются **только из Backend**, через `client.responses.create`. Ключ никогда не добавляется в браузерный бандл.
- Используется `store=False`; фотографии не принимаются. Для текста применяется строгий JSON Schema формат, затем независимая серверная валидация языка, количества и длины страниц.
- Доступ требует подтверждённой серверной сессии, допуска пилотного аккаунта и квот. Frontend перед генерацией проверяет `/api/billing/status`.
- Ошибки провайдера не раскрываются клиенту как технические подробности; применение текста и сетевая безопасность требуют отдельной проверки на реальном Preview.

**Не считать функцию запущенной, пока не выполнен реальный тест с авторизованным API-ключом, Preview и тестовым аккаунтом.**
